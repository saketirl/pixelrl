# Humanoid Sweep Handoff - 2026-05-19

## Scope

Work focused on making non-pixel Brax Slippery Humanoid learn, then checking whether increasing the number of task changes causes loss of plasticity.

Allowed edit scope was:

- `ppo_brax.py`
- `scripts/CL/brax/humanoid_sweep/`

No other code paths were intentionally modified.

## Main Finding

The non-pixel Humanoid run did not learn under the initial generalized Slippery Env wrapper settings, even with PPO hyperparameters that should have been reasonable. The successful recipe required mirroring the working pixelbrax trainer behavior more closely:

- bounded global actor log std
- tanh-bounded actor means
- running observation normalization
- CRATE state trunk
- CRATE actor and critic heads
- low learning rate, best so far `3e-5`

With Adam heads, this config learns Slippery Humanoid and shows a clear loss-of-plasticity pattern when task changes become frequent.

  - `--actor-logstd-max`

  - `--actor-logstd-init`

  - `--actor-mean-scale`
- CRATE actor and critic heads:
  - `--use-crate-head`
  - `--crate-step-size`
- CRATE state trunk:
  - `--use-crate-network`
  - `--network-crate-step-size`
- Running observation normalization:
  - `--obs-normalize`
  - `--obs-norm-clip`
- Head optimizer plumbing:
  - Adam remains the default.
  - `--heads-optimizer stiefel` routes matrix head params through `optimizers/manifold_stiefel_optax.py`.

## Sweep Launcher Changes

`scripts/CL/brax/humanoid_sweep/sweep.sh` now supports:

- `WAVE=pilot`
- `WAVE=lr`
- `WAVE=validate`

The `validate` wave maps 4 phase-count settings x 2 seeds into an 8-task SLURM array.

Important environment variables:

- `HEADS_OPTIMIZER`, default `adam`; set to `stiefel` for manifold Stiefel heads.
- `LEARNING_RATE`, best Adam/Stiefel starting point so far `3e-5`.

- `VALIDATION_PHASE_ENV_STEPS`, fast plasticity setting `999936`.

`start.sh` delegates to `sweep.sh`.

## Current Caveats

- The successful trainer behavior depends on observation normalization plus CRATE trunk/head. Removing either caused poor or inconsistent learning earlier.
- The fast plasticity benchmark is intentionally harsh: `999936` env steps per phase.
- The Stiefel run has lower throughput, so equal wall-clock comparisons are misleading; compare by environment steps.
- The 10-phase Stiefel run looked strong mid-run but dropped hard on the final high-friction phase, ending mixed rather than decisively better than Adam.
